## B4 research gate verdict (D-09) — documented deviation on mechanism detail

RESEARCH Q1 disproved D-09's fallback premise: the dotLottie core discovers theme targets ONLY via `sid` slot tags (dotlottie-rs `collect_sid_slots`); the Phase 3 canonical Lottie carries `nm` anchors but no `sid` (strictObject forbids stray keys), and `.dotlottie` packaging does not inject slots — so setThemeData on the raw canonical bytes changes zero pixels (guaranteed false theme:noop). Resolution (zero Phase 3 domain churn, D-21 spirit): pure `slotizeForTheme()` derives the themed VARIANT in the QA page (adds sid = layer nm to fill color props of anchor layers, deep-cloned); the canonical bytes remain untouched for baseline diffs. This still proves the production apply path (setThemeData + slots + wasm core IS what Phase 8 uses; only the sid annotation SITE differs — Phase 8 moves it into the compiler/packager with the same shape). No work is thrown away.
